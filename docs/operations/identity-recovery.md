# Identity-code export and import proposal

Status: proposed interaction and state model; no production application changes. The standalone prototype is captured on the local throwaway branch `prototype/identity-recovery`, commit `5de82fb`, at `prototypes/identity-recovery.html`. Its base is feature HEAD `d5bb815bf3f7b6ca912ab3512c748e8943b1e250`. Browser verification exercised all eight walkthroughs and asserted the active identity after each of their 63 button actions; this is prototype evidence, not a shipped recovery feature.

The proposal lets someone save their existing anonymous identity as a private code and later use that code on another browser or frontend origin. Import selects the identity whose projects should be accessible. It never merges projects, changes project ownership, transfers a running workflow, or changes published versions. Before switching away, the person must back up the identity they currently use.

## Current API and ownership semantics

These facts come from the implementation, rather than from an assumed account system:

| Surface                                                                                                                              | Existing behavior                                                                                                                                                                                                                                       | Consequence for recovery                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [API owner middleware](../../apps/backend/src/formlane/app.py)                                                                       | For `/api/*`, a syntactically valid `x-owner-id` takes precedence over a valid `atoms_uid` cookie. If neither is valid, the API generates a new UUID. It returns `Cache-Control: no-store` and an HttpOnly, SameSite=Lax owner cookie, secure on HTTPS. | Missing or malformed credentials can create a fresh identity. A successful response alone does not prove that an imported credential was used.                                                                           |
| `GET /api/me`                                                                                                                        | Returns the request's selected `ownerId`; it does not authenticate an email, look up an account, or verify recovery history.                                                                                                                            | Check exact equality with the candidate capability during preview. A newly generated identity is an error when a current or candidate identity already exists.                                                           |
| [Browser API client](../../apps/web/src/lib/api.ts)                                                                                  | Reads `localStorage['atoms_uid']`, sends it as `x-owner-id`, and uses `credentials: 'omit'`. `ensureOwner()` retains a module-level `ownerPromise` and rejects a bootstrap reply that differs from an existing stored identity.                         | Export must preserve the existing value. Updating local storage alone is insufficient for switching: the memoized owner and raw run/download requests must change coherently.                                            |
| [Project storage](../../apps/backend/src/formlane/storage.py)                                                                        | Project creation stores the exact `owner_id`; listing filters `Project.owner_id == owner_id`; private project lookup filters both project ID and owner, returning 404 on mismatch.                                                                      | Possession of the owner UUID grants access. | Private detail, versions, download, run, publish and restore routes                                                                  | Carry the selected owner through the storage authorization boundary.                                                                                                                                                                                    | Recovery must retain that boundary for every request. | [Application bootstrap](../../apps/web/src/App.tsx) and [private query definitions](../../apps/web/src/features/projects/queries.ts) | Private routes bootstrap the owner. The shared query client and current project query definitions have no explicit identity dimension in their inputs.                                                                                                  | A switch must fence outstanding work and clear or partition private results. The UUID syntax accepts upper- and lowercase hexadecimal characters, but owner IDs are stored and compared as text. Preserve the exact UUID spelling through export, parsing, comparison, headers, and persistence. Lowercasing an existing capability is not a safe compatibility migration. The format does not impose a UUID version or variant restriction beyond the backend's existing shape check.

## Code format and compatibility

The proposed v1 code is one ASCII line:

```text
formlane-identity:v1:11111111-1111-4111-8111-111111111111
```

This is a public synthetic example, not a credential from any environment. The grammar is the literal prefix `formlane-identity:`, the literal version `v1`, a colon, and one UUID matching the current API's 8-4-4-4-12 hexadecimal shape. The importer trims surrounding whitespace, limits input to 256 characters (256 bytes for an imported text file), and rejects unknown versions, extra fields, embedded whitespace, malformed UUIDs, URLs and bare UUIDs. It never repairs a malformed code by generating another identity. A downloaded `.txt` file contains exactly this line; the filename must not contain the UUID.

The wrapper versions the exchange format; it does not replace the backend owner ID. Export wraps the existing `atoms_uid` unchanged. After an explicitly confirmed import, production requests would still send the extracted UUID as `x-owner-id`; storage would still contain only the UUID under the existing key. Existing browsers and backend data require no migration. An old browser can keep using the same capability after another browser imports it.

The code contains no project data, API endpoint, email address, expiry, signature or encryption. Import must use the application's configured trusted API origin and must never take an endpoint from imported text. Moving between frontend origins only restores access when they use the same backend dataset. This is not a database migration or a guarantee that the code will recover projects from another environment.

A v1 syntax check detects structural mistakes, not every changed character. A different well-formed UUID is a different capability. Preview and explicit confirmation make that uncertainty visible; they do not establish an account's existence or the human's identity. Unsupported versions should provide a clear error while retaining the active identity.

## Proposed interaction

1. **Export the current identity.** Explain that anyone with the code can access and modify its private projects. Reveal the code only on request. Offer Copy and Download text file. If clipboard access is unavailable, allow selecting and copying the visible code or downloading it. Export does not alter the active identity.
2. **Enter or open a saved code.** Validate locally before any API request. Keep the active identity, private query cache and current route intact. Compare the parsed UUID with the active UUID by exact string equality; an exact match is a no-op and needs no switch or backup.
3. **Preview the target.** Use a separate, read-only candidate client with explicit candidate headers and `credentials: 'omit'`. Check `/api/me` returns the exact candidate, then read `/api/projects` under that same candidate. Do not write the candidate to local storage or reuse the globally cached owner for preview. Render the returned recent project titles in text-safe controls, the available-list limit, and an explicit empty-result message. A failed or mismatched preview leaves the current identity and its projects intact; it is never an empty successful preview.
4. **Back up the current identity before confirmation.** Export the current identity and require the person to acknowledge they have kept its code privately. Track acknowledgment against both the exact current identity and its current session generation. Neither clicking Copy/Download nor revealing the code proves that it was saved. This is an explicit user acknowledgment, not a verified file backup. A backup from an earlier identity session cannot authorize a later switch.
5. **Confirm the switch.** Show the target project preview and explain that the current projects remain under the current identity. Require a successful, current preview, current-identity backup acknowledgment and no running work or unresolved mutation. Then perform one coordinated identity transition and navigate to the target identity's project list. There is no project import, merge or transfer operation.
6. **Return later if needed.** Import the saved previous code using the same process. Back up the now-current identity before returning. Projects and publications retain their existing owners and selections.

Cancel closes and invalidates the candidate preview, clears its candidate input, and retains the current identity, projects and valid current backup. Editing the candidate invalidates the previous preview. Confirmation cannot rely on a preview for an older code. Errors must never silently replace an existing `atoms_uid` with a new identity.

## State transitions and guards

The prototype's pure reducer is isolated in its first script block. It uses explicit current identity, session generation, running-work state, import phase, candidate, preview request, preview projects, exported code owner, backup acknowledgment and private-cache owner. Its second script block binds the reducer to browser controls and performs optional clipboard/file actions.

| Action or condition                       | Result                                                                                                                                        |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Export                                    | Reveal the code for the active identity; leave ownership and preview unchanged.                                                               |
| Acknowledge backup                        | Allowed only after exporting the current identity; bind the acknowledgment to its session generation.                                         |
| Invalid or unsupported code               | Show validation failure without changing the active identity.                                                                                 |
| Same exact identity                       | Report a no-op; no preview, cache purge, backup requirement or identity change.                                                               |
| Begin preview                             | Capture candidate, source identity, request ID and session generation. Keep active projects visible.                                          |
| Successful preview                        | Make only that current candidate eligible for confirmation. An empty list is a visible valid result.                                          |
| Failed preview                            | Remove switch eligibility; preserve current identity and projects.                                                                            |
| Edit or cancel                            | Invalidate the candidate request and preview. A late response cannot restore them.                                                            |
| Confirm without preview or current backup | Reject the action; preserve identity.                                                                                                         |
| Confirm while work runs                   | Reject the switch. Finish work or explicitly cancel it and await terminal confirmation.                                                       |
| Confirm valid switch                      | Increment identity generation, clear old private state, select the candidate, reset backup/export/import state. No project ownership changes. |
| Stale response after cancel or switch     | Ignore it; never refill old caches or reset the active identity.                                                                              |
| Unexpected `newIdentity` bootstrap result | Reject replacement of an existing identity.                                                                                                   |

The demo's “Start running work” / “Finish running work” controls model the guard only. They do not execute or cancel CrewAI/DBOS workflows. The “Simulate unexpected new identity reply” control models the existing bootstrap-preservation rule; `newIdentity` is a conceptual event, not a newly added API field or endpoint.

## Production integration fences

These are requirements for a later implementation, not claims about changes made in this proposal:

- **One identity transition owner.** Serialize bootstrap, import confirmation and any deliberate new-identity action through a session coordinator. Each asynchronous operation captures an owner and a monotonically increasing generation. Check both before applying results, writing `atoms_uid`, publishing UI state or refreshing caches. Do not let a pending old `ensureOwner()` promise write its result after an import.
- **Candidate isolation.** Preview must never temporarily replace the global owner to make requests. Use its own abort controller, request identity and result state. Cancel, edit, route teardown or session change invalidates that state. Response application checks the request ID, source identity and generation even if abort was requested: abort alone is not a race fence.
- **Running work and mutations.** Freeze new private actions during confirmation. Block switching for queued/running/recovering work, a pending create/run/restore/publish/delete mutation, or an uncertain run state; recheck after asynchronous preparation and immediately before the transition. Do not infer idleness from a disconnected stream. The existing 60-project list is not an authoritative owner-wide run inventory. An owner-wide guarantee across unloaded projects and tabs requires a backend owner-scoped active-work check or an equivalent complete authoritative source, with concurrent run-start races addressed. The prototype's boolean does not establish that guarantee.
- **Abort and detach.** On a permitted switch, stop old query subscriptions, stream readers and abortable reads; detach the private route/workspace so its closures cannot mutate the new session. Clear draft conversation, candidate source, preview/download object URLs, selected version, run cursor, mutation feedback and any saved undo token associated with the old owner. Aborting transport does not roll back server mutations or cancel durable work; wait for uncertain mutations before switching.
- **Private cache boundary.** Cancel old queries before removal. Partition private query keys by identity generation or rebuild their query client at the switch. Remove old private query/mutation results and router preload data. Identity-scoped keys alone do not remove private local component state. Public published pages may keep their separate public cache, but must not carry private owner state into the viewer.
- **Bootstrap reset and persistence.** Reset or replace `ownerPromise` together with the active session. Persist the candidate only as part of the confirmed transition; handle an unavailable/failed local-storage write before enabling the new session. If transition persistence fails, retain or restore the prior identity and report failure. Do not launch B's private operations while old request paths still use A. On successful transition, all oRPC, run, stream and download paths must resolve the same selected owner.
- **`newIdentity` fencing.** Keep the current existing-owner mismatch guard. Both bootstrapping a new browser and an explicitly requested new identity must use generation checks. An API-generated UUID caused by a lost header is not consent to switch. A late bootstrap response must never recreate an old promise, overwrite the imported identity or populate the wrong cache.
- **Other tabs.** The real local-storage key is shared across same-origin tabs, but each tab currently memoizes its owner. Observe identity changes, fence the previous session immediately and require a coherent reload/rebind before allowing private actions. Coordinate confirmation with running-work state in other tabs; a storage event after a write cannot by itself prevent an already-running tab from conflicting. The standalone file intentionally does not implement storage or cross-tab coordination.

Preserve native CrewAI Flow execution, operation-level DBOS replay and the existing completion gate: Alex's validation, David's independent validation and David's approval for the exact candidate must precede saving. Identity switching does not weaken those gates, cancel work implicitly or introduce a total runtime deadline. Server cancellation and lease fencing remain the only mechanisms that fence durable workflow writes.

## Capability security and recovery limits

The UUID is a bearer capability: anyone who obtains it can exercise the authorized private API, including destructive actions. Versioning or encoding it does not make it safer, and `/api/me` is not proof of a separate account login. CORS and allowed-origin checks do not convert this into email authentication or protect against someone who already possesses the capability.

Real codes must not appear in URLs, analytics, application logs, error reports, screenshots, issue comments, recordings or third-party widgets. Treat clipboard contents and exported files as secrets. Use explicit reveal and clear transient candidate/export state on dismissal or session change. Do not display the full current UUID in the production header or include it in a download filename. The prototype deliberately displays full synthetic state to explain the model; that display is not a production UI recommendation.

The existing system has no email recovery, account-linked reset, identity revocation or capability rotation endpoint. A code is not single-use, has no application-enforced expiry, and continues to work in every browser holding it. Clearing browser storage, switching identities or generating a new UUID does not revoke old copies. Losing all copies of an identity loses this recovery route. A leaked code cannot be made safe by importing it elsewhere. A future rotation/revocation design would need server-side authority and a deliberate migration; this proposal does not claim or implement it.

## How to review the prototype in a browser

Open `/tmp/formlane-identity-prototype.html` directly. The top panel shows the active identity, accessible projects, running-work state, import phase, backup status and candidate preview after every action. Expand “Request and cache safeguards” to inspect session generation, pending/last request identity, cache owner, cleared cache and ignored-response counts.

Each walkthrough tab resets the known initial state; press its enabled numbered buttons in order:

| Walkthrough        | Expected observation                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recover and return | A retains two projects, B retains three. Switching displays the selected set; returning with A's code restores access to A's set. The private-cache panel clears on both transitions. |
| Backup required    | Confirmation is rejected before export and again before the saved-copy acknowledgment. Only preview plus current backup enables a successful switch.                                  |
| Same identity      | Re-importing A while A's work runs is a no-op. Active identity, projects, generation and cache remain unchanged.                                                                      |
| Running work       | A ready preview and acknowledged backup cannot switch while work runs. Finish the simulated work, then confirm successfully.                                                          |
| Failure and cancel | Failure leaves A active; confirmation fails. A fresh successful preview can be cancelled, again leaving A active and ineligible to switch.                                            |
| Validate codes     | Malformed UUID and future version fail locally. An unexpected fresh bootstrap identity is rejected.                                                                                   |
| Late responses     | A response delivered after cancellation is ignored. A duplicated old response delivered after switching is also ignored and cannot refill the old cache.                              |
| Empty identity     | C previews zero projects explicitly. Switching still requires A's backup and confirmation; no projects move to C.                                                                     |

Use Free play for additional review: reveal A's code, copy or download it, check the downloaded file contains the shown code, and import that file. Exercise manual copy fallback if the browser denies clipboard access. Change the candidate after a successful preview and confirm that the old preview cannot authorize a switch. Try arbitrary action order, repeated confirmation and Cancel during loading. The “Ownership stays separate” catalog should remain unchanged throughout. Reloading the file resets the in-memory state.
